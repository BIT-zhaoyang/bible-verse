# 08. 快照、投影和读模型

快照、投影和读模型都是“保存重复数据”，但目的不同。

- 快照：为了历史准确
- 投影：从事件或事实生成另一种形态
- 读模型：为了读取方便和性能

## 快照

快照保存某个时刻的数据。

例子：

```text
order_items.product_name_snapshot
order_items.unit_price_snapshot
image_generations.prompt_snapshot
invoices.billing_address_snapshot
```

快照回答：

> 当时是什么？

它不应该随着源数据变化。

## 投影

投影是从事实源转换出来的数据形态。

例如从订单和订单明细生成报表行：

```text
daily_sales_summary
- date
- gross_amount
- order_count
```

投影可以重建，通常不是最终事实源。

## 读模型

读模型为特定页面或查询优化。

```text
feed_items
- user_id
- actor_name
- action_text
- target_title
- created_at
```

它可能来自用户、关注关系、动态、评论、点赞等多张表。

读模型适合高频复杂查询，但有同步成本。

## 什么时候需要读模型

先问：

- 直接 join 是否已经足够？
- 缓存是否能解决？
- 查询是否真的慢？
- 读模型如何更新？
- 数据不一致时用户能否接受？
- 能否从事实源重建？

早期产品不要过早读模型。先把事实模型设计清楚。

## 同步方式

读模型更新方式：

- 同事务同步写入
- 异步 worker 更新
- 定时重建
- 事件驱动投影
- 手动刷新

越实时，一致性成本越高。

## 快照和读模型的区别

快照通常不能重建，因为它保存历史时刻的值。  
读模型通常应该能从事实源重建。

例如订单单价快照不能用当前商品价格重建。  
但首页 feed 读模型可以从动态事件重建。

## 本章原则

> 快照保存历史证据，读模型服务查询性能；重复数据必须说明它是否可重建、谁负责更新、哪份是真相。
