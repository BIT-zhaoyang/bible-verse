# 05. 隐私、安全、保留和合规

数据库设计也要考虑隐私和安全。

有些字段不是普通数据，而是敏感数据。

## 识别敏感数据

例子：

- 邮箱
- 手机号
- 地址
- IP
- 支付信息
- 身份证件
- 健康数据
- 私信内容

敏感数据要最小化保存。

## 加密和哈希

密码必须哈希，不是加密。

token 建议只保存 hash。

需要查询的敏感字段不能简单不可逆哈希，可能要用专门策略。

## 数据最小化

不要因为“以后可能有用”保存所有东西。

问：

- 这个字段为什么需要保存？
- 保存多久？
- 谁能访问？
- 泄漏后风险是什么？
- 用户删除时怎么办？

## 删除和匿名化

用户请求删除账号时，不一定能删除所有业务记录。

订单、发票、审计可能要保留，但可以匿名化个人信息。

```text
deleted_at
anonymized_at
```

## 访问审计

敏感数据读取也可能需要审计。

```text
sensitive_data_access_logs
- actor_id
- resource_type
- resource_id
- action
- created_at
```

## 本章原则

> 数据库设计要最小化敏感数据、明确保留期限、区分删除和匿名化，并对关键访问和修改留痕。
