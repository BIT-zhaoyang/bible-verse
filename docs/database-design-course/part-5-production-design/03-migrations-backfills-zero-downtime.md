# 03. 迁移、回填和零停机变更

数据库 schema 会随着产品演进。迁移设计不当，会导致部署失败或线上停机。

## 安全迁移思路

生产环境要避免“一步到位”的破坏性变更。

危险操作：

- 直接删除字段
- 直接改字段类型
- 给大表加 not null 且无默认处理
- 长时间锁表
- 应用代码和 schema 不兼容

## Expand and Contract

安全做法通常分两阶段。

### Expand

先新增兼容结构。

```text
新增 new_column，可空
应用开始双写 old_column 和 new_column
回填历史数据
应用切读 new_column
```

### Contract

确认稳定后再删除旧结构。

```text
停止写 old_column
删除 old_column
```

## 回填

回填大表时不要一次更新所有行。

分批处理：

```text
每次更新 1000 行
记录进度
可重试
可暂停
```

## 添加 not null

安全步骤：

1. 新增可空字段
2. 应用开始写新字段
3. 回填旧数据
4. 检查无 null
5. 加 not null 约束

## 重命名字段

直接 rename 可能导致新旧代码不兼容。

更安全：

1. 新增新字段
2. 双写
3. 回填
4. 切读
5. 删除旧字段

## 本章原则

> 线上迁移要兼容新旧代码；先扩展、回填和切流量，再收缩旧结构。
