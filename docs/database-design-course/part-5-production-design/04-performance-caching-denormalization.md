# 04. 性能、缓存和反规范化

性能优化要有层次，不要一上来就把 schema 搞复杂。

推荐顺序：

```text
清楚查询路径
加合适索引
优化查询
使用缓存
引入读模型或反规范化
分区或拆库
```

## 缓存

缓存适合读取频繁、变化不频繁的数据。

例子：

- 首页内容
- 文章详情
- 商品分类
- 用户权限摘要

缓存要设计失效策略。

常见方式：

- TTL
- 按 tag 失效
- 写入后主动失效
- 后台重建

## 计数缓存

点赞数、评论数、阅读数常存冗余字段。

```text
posts.like_count
posts.comment_count
```

事实源仍然是 likes/comments。

要决定：

- 是否要求强一致
- 是否允许短暂延迟
- 如何修复计数漂移

## 读模型

如果一个页面需要复杂 join，可以建读模型。

```text
dashboard_cards
feed_items
search_documents
```

读模型最好可重建。

## 分区

大表按时间或租户分区。

适合：

- 日志
- 事件
- 审计
- 消息
- 时序数据

分区是生产优化工具，不是早期建模默认选项。

## 本章原则

> 性能优化从查询和索引开始；缓存、反规范化、读模型和分区都要明确一致性代价和重建策略。
