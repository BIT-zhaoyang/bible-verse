# 03. 设计评审检查清单

设计完 schema 后，用这份清单自查。

## 实体

- 每张表能否用一句话说明职责？
- 是否有表承担多个生命周期？
- 哪些对象有独立身份？
- 哪些只是属性？

## 关系

- 一对一、一对多、多对多是否清楚？
- 外键放在正确一方吗？
- 多对多是否需要中间表？
- 关系本身是否有属性？
- 删除策略是否符合业务？

## 约束

- 主键是否稳定？
- 业务唯一性是否有唯一约束？
- 是否需要组合唯一或条件唯一？
- 必填字段是否 not null？
- 状态字段是否限制合法值？
- 金额和数量是否有范围约束？

## 生命周期

- 每个 status 的含义是否清楚？
- 初始状态和终态是什么？
- 合法状态转移是否明确？
- 是否需要状态事件表？
- 时间戳是否和状态一致？

## 历史和快照

- 哪些字段未来变化后不应影响历史？
- 是否需要 snapshot？
- 历史是否被 update 覆盖？
- 审计是否足够？

## 查询和索引

- 核心页面从哪张表开始查？
- 高频 where/order by 字段是否有索引？
- 组合索引顺序是否符合查询？
- 是否有过早索引？

## 生产

- 重复请求是否幂等？
- 跨表写入是否需要事务？
- 大表迁移是否安全？
- 敏感数据是否最小化？
- 删除和保留策略是否明确？

## 本章原则

> 好的设计评审不是看字段够不够，而是检查事实源、生命周期、约束、查询路径和演进风险是否清楚。
