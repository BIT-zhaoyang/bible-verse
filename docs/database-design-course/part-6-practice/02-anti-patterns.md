# 02. 常见反模式

反模式是数据库设计里的坏味道。

看到这些情况，要停下来重新思考。

## 一张万能表

一张表同时包含：

- 内容字段
- 审核字段
- 生成任务字段
- 发布字段
- 统计字段
- 权限字段

通常说明多个生命周期被混在一起。

## 多个布尔值表达流程

```text
is_approved
is_rejected
is_published
is_archived
```

复杂流程应使用 status enum。

## 没有外键

应用代码里写了 `user_id`，但数据库没有外键。

结果是迟早出现无效引用。

## 重要唯一性只靠代码

例如“一个用户只能有一个 active subscription”只靠代码检查，遇到并发可能失效。

重要规则应尽量用唯一约束兜底。

## 历史被覆盖

订单金额、发票地址、发布版本、prompt 等历史数据被当前值覆盖。

需要快照或版本表。

## JSON 逃避建模

把核心关系和状态塞进 JSON。

JSON 适合边缘 metadata，不适合核心业务事实。

## Null 含义不明

字段可空，但没人能解释 null 代表什么。

可空字段必须有业务语义。

## 读候选而不是读事实

公开页面直接读最新草稿、最新生成、最新任务。

应该读已发布、已批准、已确认的事实源。

## 本章原则

> 反模式的共同点是职责不清、规则不硬、历史不可解释、查询读错事实源。
