# 01. 从需求到 schema 的建模流程

拿到需求时，不要急着写字段。

用下面流程推导模型。

## 1. 写业务故事

用自然语言描述：

```text
谁做什么？
对什么对象？
会产生什么结果？
失败怎么办？
谁能看到？
历史是否要保留？
```

## 2. 圈名词

名词通常是候选实体：

```text
用户、订单、商品、支付、退款、发票
```

筛选是否有独立身份和生命周期。

## 3. 圈动词

动词通常暗示事件或流程：

```text
创建、支付、审核、取消、退款、发送、生成
```

判断是否需要任务表、事件表或状态变化。

## 4. 判断关系

对每对实体写：

```text
一个 A 有几个 B？
一个 B 属于几个 A？
关系本身有没有属性？
删除 A 时 B 怎么办？
```

## 5. 设计生命周期

列状态：

```text
初始状态
中间状态
终态
合法转移
```

## 6. 找事实源和快照

问：

```text
这个字段属于谁？
未来变化后历史是否要跟着变？
是否需要 snapshot？
```

## 7. 写约束

列出必须永远成立的规则：

```text
唯一性
非空
外键
金额范围
状态集合
条件唯一
```

## 8. 列查询路径

列页面和接口：

```text
详情页怎么查？
列表页怎么筛选？
后台怎么排序？
报表怎么聚合？
```

## 9. 写示例数据

手写几行数据，模拟业务流程。  
如果示例数据难写，schema 可能不自然。

## 本章原则

> 建模流程是：故事 -> 名词 -> 动词 -> 关系 -> 生命周期 -> 快照 -> 约束 -> 查询 -> 示例验证。
