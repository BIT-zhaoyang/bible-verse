# 09. 通知、邮件和用户生命周期

通知系统让网站能主动触达用户。它不仅是发送邮件，还包括触发条件、模板、偏好、退订、送达记录和失败重试。

## 通知类型

交易通知：

```text
注册验证
密码重置
支付成功
订单发货
任务完成
```

产品通知：

```text
评论回复
团队邀请
审核结果
用量提醒
```

营销和召回：

```text
每日内容
每周摘要
促销
新功能介绍
流失召回
```

交易通知和营销通知要区分。营销通知必须考虑退订。

## 通知架构

推荐流程：

```text
业务事件 -> 通知任务 -> 渲染模板 -> 发送渠道 -> 记录结果
```

常见表：

```text
notification_events
notification_deliveries
email_templates
subscriber_preferences
```

简单系统可以先只保存订阅者和发送日志。

## 渠道

- 邮件
- 站内通知
- 浏览器推送
- 短信
- Webhook
- Slack 或企业微信

MVP 通常从邮件开始。

## 用户偏好

偏好字段可能包括：

```text
daily_email_enabled
weekly_summary_enabled
marketing_enabled
language
timezone
```

如果网站面向不同地区，时区非常重要。每日内容类网站尤其如此。

## 退订

邮件订阅至少要有：

- 订阅入口
- 退订链接
- 退订记录
- 重新订阅
- 邮件类型区分

不要让用户只能通过联系客服退订。

## 常见坑

第一，业务流程里直接发送邮件，失败影响主流程。

第二，没有发送日志，无法排查。

第三，没有退订。

第四，所有邮件都走同一偏好，交易邮件被误关。

第五，没有频率控制。

## 决策清单

- 通知触发事件是什么？
- 是否异步发送？
- 使用哪些渠道？
- 是否需要模板？
- 是否需要用户偏好？
- 是否需要退订？
- 是否记录发送结果？
- 失败是否重试？
- 是否需要按时区发送？

## 练习

为 Bible Daily Verse 设计真实每日邮件订阅：

- 用户输入邮箱
- 确认订阅
- 每天按时区发送今日经文
- 记录发送结果
- 支持退订
