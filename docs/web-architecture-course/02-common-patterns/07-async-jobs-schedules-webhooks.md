# 07. 异步任务、定时任务和 Webhook

有些事情不应该在用户请求里直接完成。异步任务让系统可以处理耗时、易失败、可重试的流程。

## 什么时候异步

满足任一条件就考虑异步：

- 超过几秒
- 调用第三方服务
- 可能失败
- 需要重试
- 需要批量处理
- 不需要用户立即等待
- 需要定时执行

常见例子：

```text
AI 生成
图片压缩
视频转码
邮件发送
报表生成
支付回调
导入导出
搜索索引更新
```

## 任务表

任务表常见字段：

```text
id
type
status
input
result
error_message
attempt_count
scheduled_at
started_at
finished_at
created_at
updated_at
```

状态：

```text
pending -> processing -> succeeded
pending -> processing -> failed
failed -> pending
```

如果需要人工审核，可以加入：

```text
review_required
approved
rejected
```

## 队列

早期可以用数据库表加定时轮询。规模变大后使用队列。

典型流程：

```text
创建任务 -> 入队 -> worker 处理 -> 更新任务 -> 通知用户
```

队列要考虑：

- 重试
- 死信队列
- 并发限制
- 幂等处理
- 任务超时
- 可观测性

## 定时任务

定时任务适合：

```text
每日发布
定期清理文件
每月账单
同步第三方数据
发送每日邮件
重建搜索索引
```

定时任务要保证幂等。尤其是每日发布、账单生成这类任务，重复执行不能产生重复订单或重复发布。

## Webhook

Webhook 是第三方系统主动通知你。

常见场景：

- 支付成功
- 订阅取消
- 邮件送达或退信
- 文件处理完成
- 第三方数据变更

Webhook 处理流程：

```text
接收请求 -> 验证签名 -> 记录事件 -> 幂等检查 -> 更新业务状态 -> 返回成功
```

不要在 Webhook 里做太多耗时操作。可以记录事件后放队列处理。

## 常见坑

第一，用户请求里直接调用慢任务，导致超时。

第二，任务失败没有记录。

第三，没有重试。

第四，Webhook 没有验签。

第五，重复 Webhook 导致重复开通权益。

第六，定时任务不是幂等的。

## 决策清单

- 这个流程是否耗时？
- 是否依赖第三方？
- 失败是否需要重试？
- 是否需要任务表？
- 是否需要队列？
- 是否需要后台查看任务？
- 是否需要定时执行？
- 是否需要 Webhook 验签？
- 是否幂等？
