# 11. 数据分析、日志和运营后台

网站上线后，最重要的问题从“能不能用”变成“发生了什么、哪里出错、用户怎么用、运营怎么管理”。

## 三类后台能力

业务后台：

```text
内容管理
用户管理
订单管理
审核队列
文件管理
系统配置
```

数据分析：

```text
访问量
转化率
留存
分享次数
热门内容
任务成功率
收入
```

工程运维：

```text
错误日志
任务失败
Webhook 失败
第三方 API 失败
性能监控
告警
```

## 操作日志

后台敏感操作建议记录：

```text
id
actor_id
action
resource_type
resource_id
before
after
ip_address
created_at
```

操作日志能回答：

- 谁改了这条数据？
- 什么时候发布的？
- 为什么被拒绝？
- 哪次操作导致错误？

## 后台页面结构

常见后台：

```text
Dashboard
资源列表
资源详情
编辑页
审核页
任务列表
日志页
设置页
数据导出
```

后台设计重点是效率和可靠，不是营销感。

## 常见坑

第一，没有后台，只能直接改数据库。

第二，没有日志，出了问题只能猜。

第三，指标和目标无关。

第四，后台操作没有权限。

第五，第三方失败没有告警。

## 决策清单

- 运营每天需要看什么？
- 哪些数据需要人工管理？
- 哪些操作需要日志？
- 哪些失败需要告警？
- 是否需要任务后台？
- 是否需要数据导出？
- 是否需要配置后台？
- 是否需要分角色后台？

## 练习

为一个 AI 图片生成网站设计后台首页，至少包括：

- 今日任务数
- 失败任务
- 生成成本
- 用户用量
- 待审核结果
