# 04. 文件上传、对象存储和媒体处理

文件是网站里最容易被低估的功能之一。头像、封面、附件、商品图、视频、AI 生成图，都涉及文件系统设计。

## 核心原则

通常不要把文件本体放数据库。数据库保存元数据，文件放对象存储。

```text
文件内容 -> 对象存储
文件信息 -> 数据库
```

## 上传方案

服务器中转：

```text
浏览器 -> 应用服务器 -> 对象存储
```

优点：权限和校验简单。  
缺点：服务器带宽和超时压力大。

浏览器直传：

```text
浏览器 -> 请求签名 URL -> 对象存储 -> 回传结果
```

优点：适合大文件和高并发。  
缺点：签名、回调、确认逻辑更复杂。

系统生成后上传：

```text
后台任务 -> 生成文件 -> 上传对象存储 -> 保存 URL
```

适合 AI 图片、报表、PDF、截图。

## 公开与私有

公开文件：

```text
文章封面
商品图片
社交分享图
公开下载资源
```

可以使用公开 URL 和 CDN。

私有文件：

```text
合同
发票
用户私密文档
付费资源
```

应该使用权限校验和签名 URL。

## 文件元数据表

成熟系统建议有 `media_assets` 或 `files` 表：

```text
id
owner_id
workspace_id
storage_provider
bucket
object_key
public_url
content_type
size_bytes
width
height
checksum
visibility
status
created_at
deleted_at
```

简单系统可以先把 URL 存业务表，但至少要知道将来何时抽出文件表。

## 媒体处理流水线

图片常见处理：

- 格式校验
- 尺寸读取
- 压缩
- 裁剪
- 生成缩略图
- 生成多尺寸
- 内容安全扫描

视频常见处理：

- 转码
- 生成封面
- 多码率
- 字幕
- CDN 分发

这些通常是异步任务。

## 临时文件和清理

工具站经常产生临时文件。一定要设计清理策略：

```text
用户上传原文件：24 小时删除
处理结果：24 小时或 7 天删除
失败任务文件：定期清理
未绑定业务文件：定期清理
```

没有清理策略，存储费用会慢慢失控。

## 常见坑

第一，只存 public URL，不存 object key，后续无法删除或迁移。

第二，不限制大小和类型。

第三，私有文件用了公开 bucket。

第四，数据库保存成功但文件上传失败，产生坏链接。

第五，不处理 CDN 缓存，替换图片后用户仍看到旧图。

## 决策清单

- 文件来自用户上传还是系统生成？
- 文件公开还是私有？
- 文件是否需要长期保存？
- 是否需要尺寸、大小、checksum？
- 是否需要缩略图？
- 是否需要病毒或内容扫描？
- 是否需要浏览器直传？
- 是否需要清理任务？
- 是否需要 CDN？
