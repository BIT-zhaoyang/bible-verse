# 04. SaaS 产品

SaaS 的核心是让用户持续使用一个在线工具，并通过订阅或用量收费。

## 核心资源

```text
User
Workspace
Membership
Role
Project
BusinessResource
Subscription
UsageRecord
AuditLog
Integration
```

不同 SaaS 的业务资源不同。CRM 是客户和跟进记录，项目管理是任务和项目，表单工具是表单和提交记录。

## 核心流程

```text
注册 -> 创建工作区 -> 创建业务数据 -> 邀请成员 -> 持续使用 -> 计费 -> 留存
```

## 页面结构

营销侧：

```text
首页
价格页
功能页

登录/注册
```

产品侧：

```text
Dashboard

```

后台侧：

```text
用户管理

```

## MVP

SaaS MVP 的核心是：

```text
用户能创建某类业务数据，并持续回来使用。
```

早期可以先做个人账号，不做团队。也可以先不做复杂计费，用人工付费或免费试用验证价值。

但最好一开始就想清楚：

- 数据是否未来要归属 workspace
- 资源是否需要 owner
- 用量是否要记录
- 哪些操作未来需要权限

## 多租户

如果未来可能有团队，就要谨慎。

早期所有数据只有 `user_id`，后期迁到 `workspace_id` 会比较痛。一个折中方案是：

```text
一开始也创建个人 workspace
用户数据都归属 workspace
membership 里只有一个 owner
```

这样未来加团队更平滑。

## 计费和权益

SaaS 常见权益：

- 可创建项目数
- 成员数
- 存储空间
- 每月操作次数
- 高级导出
- API 访问
- 集成数量

权益判断要集中，不要散落在页面里。

## 常见坑

第一，所有数据只绑定 user，后期团队化困难。

第二，权限只在前端隐藏。

第三，没有用量记录，无法做套餐。

第四，没有审计日志，企业用户不信任。

第五，核心工作流被营销页设计挤压，产品体验不够高效。

## 练习

为一个“客户跟进 CRM”设计 SaaS 架构：

- 工作区
- 成员
- 客户
- 跟进记录
- 角色权限
- 套餐限制
