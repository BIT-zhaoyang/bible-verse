# 02. 工具型网站和 AI 产品

工具型网站的核心是让用户输入某些东西，系统处理后返回结果。AI 产品通常是工具型网站的一个现代分支。

## 典型例子

- 图片压缩
- PDF 转换
- 二维码生成
- AI 写作
- AI 图片生成
- Logo 生成
- 文本摘要
- 视频转字幕

## 核心资源

```text
User
Input
Job
Result
File
UsageRecord
Plan
```

AI 产品还会有：

```text
Prompt
Model
Generation
Review
Template
```

## 核心流程

同步小工具：

```text
用户输入 -> 立即处理 -> 展示结果
```

异步工具：

```text
用户上传/输入 -> 创建任务 -> 后台处理 -> 保存结果 -> 通知/展示/下载
```

AI 生成：

```text
输入 Prompt -> 创建生成任务 -> 调用模型 -> 存储结果 -> 展示结果 -> 重新生成/下载/分享
```

## MVP

工具站 MVP 要打通：

```text
输入 -> 处理 -> 结果
```

不一定需要登录。很多工具可以先从匿名使用开始。

MVP 可以暂缓：

- 历史记录
- 批量处理
- 用户系统
- 支付
- 模板库
- 团队协作

但不要忽略：

- 输入校验
- 文件大小限制
- 错误状态
- 处理超时
- 临时文件清理

## 成熟演进

工具站成熟后常见演进：

- 用户登录和历史记录
- 批量任务
- 队列和 worker
- 用量限制
- 付费套餐
- API 调用
- 模板库
- 团队共享
- 结果管理

## AI 产品的特殊问题

AI 产品要额外考虑：

- 模型调用成本
- 生成失败
- 内容安全
- 结果质量不稳定
- 重新生成
- Prompt 版本
- 用户用量
- 生成结果存储

如果 AI 输出会公开发布，通常需要审核或质量检查。

## 数据模型提示

不要只保存最终结果。最好保存一次生成尝试：

```text
generation_jobs
- input_snapshot
- provider
- model
- status
- result_url
- error_message
- cost
- created_at
```

这样你才能调试失败、统计成本、支持重新生成。

## 常见坑

第一，同步请求里直接跑耗时任务。

第二，不记录失败原因。

第三，AI 结果覆盖旧结果，无法比较版本。

第四，没有用量限制，成本失控。

第五，文件处理结果长期不清理。
