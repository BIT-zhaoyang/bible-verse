# 05. 社区和 Marketplace

社区和 Marketplace 都是多边参与系统。难点不在页面，而在互动、信任、治理和匹配。

## 社区网站

核心资源：

```text
User
Post
Comment
Reaction
Follow
Topic
Notification
Report
ModerationAction
```

核心流程：

```text
用户发布内容 -> 其他用户互动 -> 系统分发 -> 通知召回 -> 审核治理
```

MVP：

```text
发帖
列表
详情
评论
管理员删除
```

成熟能力：

- 关注
- 推荐
- 通知
- 举报
- 审核
- 积分
- 等级
- 私信
- 反作弊

社区最重要的问题是冷启动。没有内容，用户不会互动；没有用户，没人生产内容。

## Marketplace

Marketplace 是供给方和需求方匹配并交易的平台。

核心资源：

```text
Provider
Customer
Listing
Availability
Booking
Order
Payment
Review
Dispute
```

核心流程：

```text
供给入驻 -> 发布服务 -> 需求搜索 -> 匹配/预约 -> 支付 -> 履约 -> 评价 -> 争议处理
```

MVP 可以先人工撮合：

```text
供给列表 + 需求表单 + 人工联系
```

成熟后再做：

- 在线预约
- 支付托管
- 自动匹配
- 双边评价
- 争议处理
- 平台抽佣

## 共同难点

信任：

```text
身份认证
评价
举报
审核
履约记录
```

分发：

```text
信息流
搜索
推荐
排序
曝光规则
```

治理：

```text
内容审核
用户封禁
风控
争议处理
操作日志
```

## 常见坑

第一，只做发布和浏览，没有治理能力。

第二，社区没有通知，用户不会回来。

第三，Marketplace 过早自动化，供需还没验证。

第四，没有评价和争议机制，交易信任不足。

第五，推荐和排序规则不透明，运营无法干预。

## 练习

设计一个“本地摄影师预约平台”的 MVP。判断哪些先人工处理，哪些必须系统化。
