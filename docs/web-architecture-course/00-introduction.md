# 00. 课程导论：从功能清单到架构能力

很多人刚开始做网站时，会把网站理解成一个功能清单：

```text
登录
上传
搜索
支付
评论
分享
后台
```

这没有错，但还不够。功能清单告诉你“要做什么”，却没有告诉你“为什么这样组织”“哪些功能应该先做”“数据该如何流动”“哪些状态不能混乱”“哪些问题未来一定会爆出来”。

这套课程要训练的是架构能力。

架构能力不是一上来就画复杂图，也不是背诵各种高级名词。架构能力首先是拆解能力：

```text
把一个模糊的网站想法，拆成可以设计、可以实现、可以演进的系统。
```

## 你最终要掌握什么

学完这套课程，你应该能做到五件事。

第一，看懂一个网站的类型。

比如一个网站表面上是“每日经文”，本质可能是：

```text
内容站 + AI 生成系统 + 审核后台 + 定时发布 + 社交传播
```

第二，找出核心资源。

例如 Bible Daily Verse 的核心资源不是“页面”，而是：

```text
Verse
ImageGeneration
DailyPublication
```

第三，画出状态流转。

例如生成图片不是一个布尔字段，而是：

```text
pending -> processing -> review_required -> approved/rejected/failed
```

第四，为每个功能选择合适方案。

例如上传文件时，你要知道：

```text
小文件可以服务器中转
大文件适合浏览器直传对象存储
私有文件需要签名 URL
公开图片适合 CDN
临时文件需要清理
```

第五，知道 MVP 和成熟系统的区别。

初版网站不需要把所有能力做满，但必须保留核心闭环。你要知道哪些地方可以简化，哪些地方不能乱来。

## 为什么不能只学“怎么实现功能”

单独学功能实现，容易产生一种错觉：只要我会登录、上传、支付、搜索，我就能做任何网站。

这个想法只对了一半。

网站确实由功能组成，但网站不是功能的随机堆叠。真正决定网站形态的是：

- 谁在使用它
- 他们要完成什么任务
- 网站管理什么资源
- 资源如何被创建、修改、审核、发布、交易或删除
- 哪些操作需要权限
- 哪些流程需要异步
- 哪些页面是入口
- 网站靠什么增长
- 网站靠什么赚钱

功能是积木，架构是积木之间的关系。

## 本课程的核心公式

以后分析任何网站，都先写这条公式：

```text
网站 = 角色 + 资源 + 行为 + 状态 + 权限 + 页面 + 后台流程 + 外部服务 + 增长路径 + 商业闭环
```

举例：

```text
电商网站 =
买家/商家/管理员
+ 商品/购物车/订单/支付/库存
+ 浏览/加购/下单/付款/发货/退款
+ 待支付/已支付/已发货/已完成/已退款
+ 买家权限/商家权限/平台权限
+ 商品页/结算页/订单页/商家后台
+ 支付回调/库存扣减/发货通知
+ 支付服务/物流服务/邮件服务
+ SEO/广告/复购
+ 商品销售或平台抽佣
```

这就是架构视角。

## 课程如何组织

第一卷先训练思维框架。

第二卷建立通用功能模式库。你会把登录、上传、搜索、支付、通知等能力学成“可选择方案”，而不是只学一个写法。

第三卷讲网站类型。你会看到内容站、电商、SaaS、社区、工具站、Marketplace 等如何组合模式。

第四卷讲技术决策。它回答“同一个功能为什么有多种实现方式”。

第五卷通过案例拆解真实网站。

第六卷是练习册。因为架构能力必须靠练。

## 你应该如何使用这套课程

每读完一章，做三件小事：

1. 写出这一章解决的问题。
2. 找一个真实网站，判断它是否使用了这个模式。
3. 想一想如果自己实现，第一版会怎么简化，成熟版会怎么演进。

如果只是读，你会觉得都懂。如果能拆，你才是真的会。
