# 04. 安全、隐私、可靠性和可运维性

架构设计不只是功能能跑，还要让系统安全、可靠、可排查。

## 安全基础

常见安全边界：

- 身份认证
- 服务端权限校验
- 输入校验
- CSRF 防护
- XSS 防护
- 密钥不暴露给浏览器
- 文件类型和大小限制
- Webhook 验签
- 速率限制

不要把“前端不显示按钮”当安全。

## 隐私

隐私设计要问：

- 收集哪些个人数据？
- 为什么需要？
- 保存多久？
- 谁能访问？
- 用户能否删除？
- 是否会发给第三方？

即使早期项目，也要避免过度收集。

## 可靠性

可靠性不是永不出错，而是出错时可恢复。

关键做法：

- 状态记录
- 错误信息
- 重试机制
- 幂等处理
- 操作日志
- 告警
- 手动修复后台

AI、支付、邮件、对象存储都需要失败路径。

## 可运维性

可运维性回答：

```text
出问题时，我如何知道？
知道后，我如何定位？
定位后，我如何修复？
修复后，我如何确认？
```

需要：

- 日志
- 指标
- 任务后台
- 失败列表
- 操作审计
- 配置管理

## 常见坑

第一，没有错误日志。

第二，定时任务失败没人知道。

第三，后台操作没有审计。

第四，密钥暴露到前端。

第五，用户上传文件没有限制。

第六，外部服务失败后数据进入半完成状态。

## 决策清单

- 哪些接口需要登录？
- 哪些操作需要角色权限？
- 是否有输入校验？
- 文件上传是否安全？
- 密钥是否只在服务端？
- 异步任务失败是否可见？
- 是否有重试和幂等？
- 是否有日志和告警？
- 是否需要数据删除机制？
