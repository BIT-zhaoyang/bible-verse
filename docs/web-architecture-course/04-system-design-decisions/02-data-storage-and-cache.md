# 02. 数据存储、缓存和读写路径

数据怎么存、怎么读、怎么缓存，决定网站能否稳定扩展。

## 数据类型

业务数据：

```text
用户、文章、商品、订单、任务
```

文件数据：

```text
图片、视频、附件、生成物
```

搜索数据：

```text
索引、关键词、排序字段
```

分析数据：

```text
访问日志、事件、指标
```

缓存数据：

```text
页面缓存、查询缓存、会话缓存
```

不同数据不要都塞进一个系统。

## 存储选择

关系型数据库：

```text
适合核心业务数据、事务、关系、约束
```

对象存储：

```text
适合文件和生成资产
```

搜索引擎：

```text
适合全文搜索和复杂排序
```

缓存：

```text
适合热点读取、会话、临时状态
```

数据仓库或分析工具：

```text
适合大量行为事件和报表
```

## 读写路径

简单读：

```text
页面 -> 数据库 -> 渲染
```

缓存读：

```text
页面 -> 缓存 -> 数据库回源
```

写入后更新缓存：

```text
写数据库 -> 失效缓存 -> 下一次读取重建
```

异步同步：

```text
写数据库 -> 发布事件 -> 更新搜索索引/分析系统
```

## 缓存策略

缓存适合读多写少的数据。

常见缓存对象：

- 首页内容
- 热门文章
- 商品详情
- 分类列表
- 用户会话
- API 结果

缓存要考虑失效：

```text
什么时候刷新？
谁触发刷新？
旧数据能接受多久？
手动发布后是否立即可见？
```

## 常见坑

第一，过早加缓存，掩盖数据模型问题。

第二，缓存失效不清楚，用户看到旧数据。

第三，把文件存在数据库。

第四，搜索索引和数据库不一致。

第五，没有唯一约束，只靠代码避免重复。

## 决策清单

- 核心业务数据是否需要事务？
- 文件是否放对象存储？
- 是否真的需要缓存？
- 哪些页面可以接受旧数据？
- 写入后如何刷新缓存？
- 是否需要搜索索引？
- 是否需要分析数据单独存？
